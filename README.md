# Kairi Analytics

Клиентский дашборд технического анализа криптовалют. Свечной анализ опирается на книги Стива Нисона «Японские свечи. Графический анализ финансовых рынков» и «За гранью японских свечей. Новые японские методы графического анализа». Числовые фильтры, баллы, правила риска и статистические проверки являются настройками проекта, а не цитатами или универсальными правилами из книг.

## Возможности

### Обзор рынка

- Режим рынка и структурный тренд по закрытым свечам.
- Контекст старших таймфреймов.
- Consensus Score — эвристическая оценка согласия торговых сценариев, а не вероятность успеха.
- Подтверждённые свечные формации и торговые сценарии с входом, стопом, целью и исходным R:R.
- Зоны поддержки и сопротивления, объёмный контекст и цены в реальном времени.

### Детальный анализ

Страница Analysis объединяет:

1. Контекст рынка, объём и каскад старших таймфреймов.
2. Свечной график с индикаторами, формациями, окнами и зонами S/R.
3. Поддержку, сопротивление и полярность уровней.
4. Свечные формации с описанием и состоянием подтверждения.
5. Торговые сценарии и расчёт размера позиции.
6. RSI, MACD и дополнительный объёмный анализ.
7. Методы из книги «За гранью японских свечей»: индекс разницы, three-line break, Renko и Kagi.

### Журнал и бэктест

- Журнал хранит сценарии, фактические выходы, P&L и статистику в локальном хранилище браузера. Данные не синхронизируются между устройствами и исчезают после очистки данных сайта.
- Бэктест использует только закрытые бары и fresh confirmed-события. Одна формация даёт не более одного входа.
- Вход привязан к фактическому закрытому бару подтверждения; для модели, завершённой собственной структурой, — к последнему бару формации.
- Результат учитывает комиссию и проскальзывание. Статистика включает win rate, expectancy в R, profit factor, просадку и walk-forward-проверку.

## Что взято из книг Нисона

### Свечные формации и контекст

Детектор учитывает геометрию тел и теней, последовательность свечей и необходимый предшествующий тренд. Разворотная формация не создаёт нужный контекст сама: например, бычья модель должна появляться после снижения, а медвежья — после подъёма. Для формаций переменной длины сохраняется фактический диапазон всей модели.

Общий сканер `pattern_scanner.ts` используется интерфейсом, генератором сигналов и бэктестом, поэтому одна и та же история не даёт разные границы формации в разных частях приложения.

### Подтверждение

Книги не предписывают одинаковую проверку каждой модели. В проекте отдельное подтверждение требуется только для выбранных формаций; остальные считаются завершёнными после закрытия последней свечи собственной структуры.

Для ожидающих сценариев:

- проверяются только последующие закрытые свечи;
- подтверждение и отмена имеют фактические индексы баров;
- вход происходит по закрытию бара подтверждения, а не задним числом по последней свече формации;
- отменённые и истёкшие сценарии исключаются;
- три бара ожидания — настройка проекта.

### Поддержка, сопротивление, полярность и окна

Книжные ориентиры включают прежние экстремумы, полярность пробитых уровней, длинные тела и окна. Восходящее окно задаётся условием `low текущей свечи > high предыдущей`, нисходящее — `high текущей свечи < low предыдущей`.

Заполнение окна и окончательный прорыв различаются:

- восходящее окно заполнено при возврате к его основанию, но прорвано только при закрытии ниже основания;
- нисходящее окно заполнено при возврате к его вершине, но прорвано только при закрытии выше вершины.

Для криптовалютного непрерывного рынка отображение окон отключено настройкой проекта. Минимальная ширина окна 1% и лимит показанных окон также являются фильтрами проекта.

### Правило множества технических приёмов

Согласование независимых методов помогает оценивать рынок, но книги не устанавливают обязательные «ровно три голоса» для каждого входа. Consensus Score, его веса и пороги — эвристика проекта. Противоположные сценарии снижают согласие, а не складываются как одинаково положительные голоса.

## Методы из книги «За гранью японских свечей»

Все четыре построения используют цены закрытия и доступны на странице Analysis. Само построение графика не является торговым сигналом.

### Индекс разницы

Рассчитывается как:

```text
((close - SMA(close, period)) / SMA(close, period)) × 100
```

До накопления полного окна SMA значение не определено; EMA или неполная SMA не подставляются.

### Three-line break

Продолжение требует превышения последнего соответствующего экстремума. Для разворота используется диапазон последних одной–трёх линий; простого касания недостаточно. Разворотная линия начинается от конечной цены предыдущей линии.

### Renko

Используется фиксированный размер кирпича. Одно закрытие может породить несколько кирпичей. Для смены направления требуется движение на два кирпича от последнего экстремума.

### Kagi

Линия продолжается на любую величину в текущем направлении и разворачивается только после обратного движения на заданный порог. Поддерживаются фиксированный и процентный пороги. Толщина линии меняется между «инь» и «ян» при переходе через предыдущее плечо или талию.

## Настройки и эвристики проекта

Следующие параметры не выдаются за книжные законы:

- EMA/RSI/MACD, числовые пороги тренда и силы движения;
- кластеризация ZoneVoter, минимальное число голосов и оценка силы зоны по касаниям;
- фильтр исходного R:R ≥ 2, ограничения риска и расстояния до цели;
- структурные цели и ATR-ограничения;
- трёхбарное окно ожидания подтверждения;
- эвристические баллы качества, согласия, фазы рынка и свободы пути цены;
- position sizing с фиксированным риском;
- издержки, статистические критерии и walk-forward-параметры бэктеста;
- дополнительный фазовый анализ Вайкоффа и OHLCV-прокси объёмной дельты.

Поле `confidence` сохранено в части внутренних типов ради совместимости, но его значение не является статистической вероятностью прибыли. В интерфейсе такие величины обозначаются как баллы или согласие.

## Источники данных

- REST Bybit — криптовалютные свечи и тикеры;
- WebSocket Binance — обновление криптовалютных цен в реальном времени;
- Cboe Delayed Quotes — основной источник дневной OHLCV-истории, текущего дневного бара и внутридневных OHLCV акций США, без API-ключа;
- Twelve Data — независимый резерв для акций и основной источник глубокой внутридневной истории; серверный ключ `KAIRI_TWELVEDATA_API_KEY` нужен только для этой ветки.

Акции загружаются через `server/quotes_server.py`: Cboe и Twelve Data автоматически резервируют друг друга, ответы кэшируются, а дневная история и тикер карточки используют один запрос. Недельные и месячные бары Cboe собираются из дневного ряда. Публичные котировки Cboe задержанные и не являются гарантированным биржевым real-time потоком. При полном отказе внутридневного резерва Cboe доступна только текущая торговая сессия; для глубокой истории и бэктеста рекомендуется настроить Twelve Data.

Сетевые ошибки, таймауты и повторные запросы обрабатываются общим HTTP-слоем. Структурный анализ и торговые сценарии не используют незакрытый live-бар. Приложение не отправляет торговые ордера и не получает доступ к брокерскому аккаунту.

## Установка и запуск

Требуется Node.js 20 или новее.

```bash
npm ci
npm run dev
```

Dev-сервер доступен по адресу `http://localhost:3000`.

### Проверки качества

```bash
npm run typecheck
npm test
npm run build
```

Production-сборка создаётся в `dist/`. Локальный просмотр сборки:

```bash
npm run preview
```

Проверки также настроены в `.github/workflows/ci.yml` для push и pull request.

## Сборка и перенос

`./deploy.sh` без аргументов выполняет проверки и сборку. Дополнительные режимы и конфигурации для статического хостинга находятся в `deploy.sh`, `netlify.toml`, `vercel.json` и каталоге `deploy/`.

Docker-сборка:

```bash
docker build -t nison-analytics .
docker run -d -p 80:80 --name nison-analytics nison-analytics
```

Для SPA на собственном сервере все неизвестные маршруты должны возвращать `index.html`, а статические ресурсы должны отдаваться без изменения путей сборки.
