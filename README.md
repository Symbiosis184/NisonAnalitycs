# Kairi Analytics - Профессиональный дашборд для крипто-трейдинга

Профессиональный дашборд для технического анализа криптовалют на основе методологии Стива Нисона.

## 🚀 Возможности

### 📊 Обзор рынка по методологии Нисона

Дашборд построен в соответствии с принципами Стива Нисона:

**1. Контекст рынка**
- Режим рынка (ВОСХОДЯЩИЙ/НИСХОДЯЩИЙ/БОКОВИК)
- Определение тренда на основе EMA 20/50/200
- Consensus Score (0-5) - сколько индикаторов согласны

**2. Паттерны с подтверждением**
- 30+ свечных паттернов по Нисону
- Автоматическое подтверждение следующей свечой
- Фильтрация по контексту (тренд, объём, уровни)
- Модификаторы: (У ПОДДЕРЖКИ), (ОБЪЁМ), (С ГЭПАМИ)

**3. Ключевые уровни S/R**
- ZoneVoter - голосование за зоны (свинги, MA, Фибоначчи, объёмы)
- Сильные зоны (≥3 голосов)
- Адаптивный tolerance для разных ценовых диапазонов

**4. Объёмный анализ**
- Сравнение текущего объёма со средним
- Визуальная индикация повышенного/пониженного объёма
- Объём как подтверждение движения

**5. Правило множества технических приёмов**
- Consensus Score показывает силу сигнала
- Минимум 3 независимых подтверждения для входа
- Уверенность в процентах

**Торговые сигналы:**
- Автоматическая генерация через SignalGenerator
- Фильтрация по R:R ≥ 2:1
- Расчёт стопов по экстремуму всей формации
- Расчёт целей по зонам S/R
- Качество сигнала (50-95%)

**Данные:**
- Реальные данные с Bybit API
- Автообновление каждую минуту
- 8 основных торговых пар

## 🎯 Структура дашборда

### Dashboard (Обзор рынка)

Каждая карточка показывает:
1. **Контекст** - тренд и режим рынка
2. **Цена** - актуальная цена с изменением за 24ч (real-time через WebSocket)
3. **Consensus Score** - сила сигнала (0-5)
4. **Подтверждённые паттерны** - только подтверждённые паттерны
5. **Торговые сигналы** - подтверждённые сигналы с R:R и качеством
6. **Ключевые уровни** - поддержка и сопротивление
7. **Объём** - сравнение с средним

**Real-time обновление:**
- WebSocket подключение к Binance для мгновенного обновления цен
- Индикатор "Real-time" показывает активное подключение
- Автоматическое переподключение при обрыве связи

### Analysis (Детальный анализ)

Страница анализа построена в порядке приоритета Нисона:
1. **Контекст рынка** - режим, consensus, объём
2. **График** - свечной график с EMA и зонами S/R
3. **Зоны поддержки/сопротивления** - по методологии Нисона (ZoneVoter):
   - Свинг-минимумы/максимумы
   - Полярность (пробитые уровни меняют роль)
   - MA50, MA65, MA200 как динамические уровни
   - Объёмные климасы
   - Середины длинных тел свечей
   - Психологические круглые числа
   - Кластеризация близких уровней (0.5% tolerance)
   - Голосование за зоны (минимум 3 голоса = сильная зона)
   - Количество касаний и последнее касание
4. **Паттерны** - с подтверждением и описаниями
5. **Торговые сигналы** - с расчётом стопов/целей
6. **Индикаторы** - RSI, MACD, сила тренда

## 🔧 Установка и запуск

### Быстрый старт

```bash
# Установка зависимостей (Node.js 20+)
npm ci

# Запуск в режиме разработки
npm run dev
```

Приложение будет доступно по адресу: **http://localhost:3000**

**Важно:** приложение полностью клиентское, работает автономно с публичными API Bybit/Binance без ключей. Бэкенд не требуется. В dev-режиме vite-сервер отдаёт мягкий CSP-заголовок (`vite.csp.ts`), чтобы политика безопасности проверялась и локально.

### Проверки качества

```bash
npm run typecheck   # tsc --noEmit
npm test            # vitest run (юнит-тесты аналитического ядра)
npm run build       # production-сборка в dist/
```

Все проверки автоматически выполняются в CI (`.github/workflows/ci.yml`) на каждый push/PR.

### Деплой (П.4)

Единый скрипт `./deploy.sh` (или `npm run deploy`) выполняет `npm ci` → typecheck → тесты → `npm audit` → сборку, затем публикует на выбранную площадку:

```bash
./deploy.sh                      # только проверки + сборка в dist/
./deploy.sh netlify              # публикация на Netlify (нужен NETLIFY_AUTH_TOKEN)
./deploy.sh vercel               # публикация на Vercel (нужен VERCEL_TOKEN)
./deploy.sh rsync user@host:/var/www/nison-analytics   # загрузка на свой сервер
```

Готовые конфигурации хостингов в репозитории — **все они отдают CSP и другие защитные заголовки**:

| Площадка | Файл | Особенности |
|---|---|---|
| Netlify | `netlify.toml` | build command со всеми проверками, SPA-fallback, заголовки безопасности |
| Vercel | `vercel.json` | framework=vite, заголовки безопасности, no-cache для index.html |
| Любой static-хостинг с поддержкой `_headers` | `public/_headers` | дублирует набор заголовков (Netlify читает его тоже) |
| Nginx / Docker | см. «Перенос на VPS» ниже | добавьте `add_header Content-Security-Policy ...` из `public/_headers` |

Превью production-сборки локально: `npm run preview` (http://localhost:4173).

## 📚 Методология Стива Нисона

Вся логика анализа основана на книгах Стива Нисона:
- "Японские свечи" (Japanese Candlestick Charting Techniques)
- "За гранью японских свечей" (Beyond Candlesticks)

### Ключевые принципы:

**1. Контекст важнее паттерна**
- Паттерны работают только в правильном контексте
- Сначала определяем тренд, потом ищем паттерны

**2. Подтверждение следующей свечой**
- Каждый паттерн должен быть подтверждён
- Без подтверждения паттерн не работает

**3. Объём подтверждает движение**
- Повышенный объём усиливает сигнал
- Низкий объём - слабость сигнала

**4. Правило множества технических приёмов**
- Минимум 3 независимых сигнала для входа
- Consensus Score показывает силу

**5. Стоп за экстремумом формации**
- Стоп-лосс за экстремумом ВСЕЙ формации
- Не за одной свечой, а за всей моделью

**6. Уровни S/R - ключевые точки (ZoneVoter)**
- Уровни - это ЗОНЫ, а не точные цены
- Количество касаний определяет силу зоны
- Объём подтверждает значимость
- Полярность: пробитое сопротивление становится поддержкой
- Кластеризация близких уровней (0.5% tolerance)
- Голосование за зоны из 6 источников:
  1. Свинг-минимумы/максимумы
  2. Полярность (пробитые уровни)
  3. MA50, MA65, MA200 (динамические уровни)
  4. Объёмные климасы
  5. Середины длинных тел свечей
  6. Психологические круглые числа
- Минимум 3 голоса = сильная зона
- Вход только у сильных зон

**7. Risk/Reward минимум 2:1**
- Каждый сигнал фильтруется по R:R
- Сигналы с R:R < 2:1 отклоняются

**8. Журнал сигналов**
- Все сигналы сохраняются в журнал
- Автоматическая проверка достижения цели/стопа
- Статистика win rate, средний P&L, средний R:R

## 🎯 SignalGenerator - Генерация торговых сигналов

### Приоритеты сигналов:

**1. Высокоприоритетные** (многокомпонентные)
- Утренняя/Вечерняя звезда
- Покинутый младенец
- Три звезды
- Башенная вершина/дно
- Три горы/реки
- Три метода
- Удержание на татами
- Лестничное дно
- Две взлетевшие вороны
- Тасуки

**2. Среднеприоритетные** (двухсвечные)
- Поглощения
- Просвет/завеса
- Семейство "шеи"
- Контратака
- Разделение
- Линия пояса
- Пинцеты

**3. Низкоприоритетные** (односвечные с условиями)
- Харами (только у уровня!)
- Харами-крест (только у уровня!)
- Молоты
- Повешенный/падающая звезда
- Спружинивание
- Доджи (с учётом частоты и контекста)

### Расчёт стопов и целей:

**Стоп-лосс:**
- По экстремуму всей формации (не одной свечи!)
- Для односвечных: за экстремумом сигнальной свечи
- Для двухсвечных: за экстремумом обеих свечей
- Для трёхсвечных: за экстремумом всех трёх свечей

**Цель:**
- По ближайшей сильной зоне S/R
- Минимальный R:R = 2:1
- Фильтрация сигналов с R:R < 2:1

**Качество сигнала:**
- Базовое качество от типа паттерна (50-75%)
- +15% за подтверждение следующей свечой
- +8% за повышенный объём
- +7% за нахождение у уровня
- +5% за модификаторы (у поддержки, с объёмом)
- +30% за комбо (2+ паттерна одновременно)

### Подтверждение сигналов (по Нисону):

**Все сигналы и паттерны проходят строгую проверку подтверждения:**

**Для бычьих сигналов:**
- Следующая свеча должна быть бычьей
- Закрытие следующей свечи должно быть ВЫШЕ максимума ВСЕЙ формации (не одной свечи!)
- Только после подтверждения сигнал считается валидным

**Для медвежьих сигналов:**
- Следующая свеча должна быть медвежьей
- Закрытие следующей свечи должно быть НИЖЕ минимума ВСЕЙ формации (не одной свечи!)
- Только после подтверждения сигнал считается валидным

**Отображение:**
- На графике показываются только подтверждённые паттерны
- В секции "Обнаруженные паттерны" отображаются только подтверждённые
- В секции "Торговые сигналы" отображаются только подтверждённые сигналы
- Неподтверждённые паттерны игнорируются (согласно методологии Нисона)

**Исправления в логике подтверждения:**
- ✅ Исправлена проверка подтверждения для многокомпонентных паттернов
- ✅ Теперь проверяется закрытие относительно всей формации (patternHigh/patternLow)
- ✅ Добавлена функция `checkConfirmation()` для точной проверки
- ✅ Исправлена проверка близости к уровням (atLevel) через ZoneVoter
- ✅ Полностью переписана функция `findSignals()` для поиска всех подтверждённых сигналов
- ✅ Каждый паттерн проверяется относительно своей следующей свечи (не последней свечи массива)
- ✅ Сигналы фильтруются по R:R ≥ 2:1
- ✅ Возвращаются топ-5 сигналов по качеству

**Критические исправления:**
- ✅ Паттерны теперь анализируются по методологии Нисона (проверка подтверждения следующей свечой)
- ✅ Торговые сигналы теперь отображаются в Dashboard и Analysis
- ✅ Журнал сигналов корректно сохраняет подтверждённые сигналы
- ✅ Логика подтверждения соответствует книге "Японские свечи" Стива Нисона
- ✅ **Real-time цены** через WebSocket Binance с индикатором подключения
- ✅ **Защита от дубликатов** - проверка при добавлении сигнала в журнал
- ✅ **Исправлено удаление сигналов** - корректное обновление состояния
- ✅ **Отображение всех паттернов** на графике (не только топ-1)

**Исправления логики генерации сигналов:**
- ✅ **Контекстная фильтрация по тренду** - сигналы соответствуют текущему тренду рынка
  - Разворотные паттерны (звёзды, младенец) могут идти против тренда
  - Продолжительные паттерны должны соответствовать тренду
- ✅ **Улучшенный расчёт цели (target)**:
  - Для long: ищем сильную зону сопротивления выше цены входа
  - Для short: ищем сильную зону поддержки ниже цены входа
  - Если сильных зон нет, используем ATR × 3 для расчёта цели
- ✅ **Проверка реалистичности сигнала**:
  - Стоп-лосс: 0.5% - 10% от цены входа
  - Тейк-профит: 1% - 20% от цены входа
  - Сигналы за пределами этих диапазонов отклоняются
- ✅ **Приоритет сильных зон** - выбираются зоны с ≥3 голосами
- ✅ **Сортировка по расстоянию** - выбирается ближайшая сильная зона

## 📓 Журнал сигналов

### Функциональность:

**Автоматическое сохранение сигналов:**
- ✅ Все подтверждённые торговые сигналы автоматически сохраняются в журнал
- ✅ Защита от дубликатов - один и тот же сигнал не будет сохранён дважды
- ✅ Автоматическое логирование в консоль при сохранении

**Автоматическое отслеживание статусов:**
- ✅ Проверка достижения цели/стопа каждые 30 секунд через WebSocket
- ✅ Автоматическое обновление статуса сигнала при достижении target или stop
- ✅ Расчёт P&L в процентах и абсолютных значениях
- ✅ Автоматическое истечение по времени (7 дней для D, 1 день для внутридневных)

**Статистика:**
- Win Rate - процент успешных сигналов
- Средний P&L - средняя прибыль/убыток
- Средний R:R - среднее соотношение риск/прибыль
- Количество активных/закрытых сигналов
- Общее количество сигналов

**Управление:**
- Фильтрация по статусу (все/активные/закрытые)
- Экспорт журнала в JSON
- Импорт журнала из JSON
- Удаление отдельных сигналов (исправлено)

**Статусы сигналов:**
- ⏳ **Активен** - сигнал ожидает достижения цели/стопа
- ✓ **Цель достигнута** - сигнал успешно закрыт по тейк-профиту
- ✗ **Стоп сработал** - сигнал закрыт по стоп-лоссу
- ⏰ **Истёк** - сигнал не достиг цели/стопа за отведённое время

### Как использовать:

1. **Автоматическое сохранение:**
   - Откройте страницу Analysis для любого символа
   - Все подтверждённые торговые сигналы автоматически сохраняются в журнал

## 🚀 Определение начала тренда (8 признаков Нисона)

Система анализирует 8 независимых признаков для определения начала нового тренда:

1. **Свечные разворотные сигналы** (гл. 4-6) - молоты, звёзды, поглощения в экстремумах
2. **Пробой уровней на объёме** (гл. 7, 15) - подтверждение пробоя повышенным объёмом
3. **Полярность уровней** (гл. 11) - пробитое сопротивление становится поддержкой
4. **Незакрытые окна/гэпы** (гл. 7) - гэпы в направлении тренда
5. **Пересечения скользящих средних** (гл. 13) - золотой/мёртвый крест MA10/MA65
6. **Дивергенции RSI** (гл. 14) - расхождение цены и осциллятора
7. **Рост объёма/открытого интереса** (гл. 15) - подтверждение движения
8. **Спружинивание** (гл. 11) - ложный пробой с возвратом

**Требование:** минимум 3 голоса из 8 для подтверждения начала тренда.

### Вариант 1: Статический хостинг (проще)

**Требования:**
- VPS с Ubuntu 20.04+ или Debian 11+
- Nginx
- Домен (опционально)

**Шаги:**

1. **Сборка проекта локально:**
```bash
npm run build
```

2. **Загрузка на сервер:**
```bash
ssh user@your-vps-ip
sudo mkdir -p /var/www/nison-analytics
sudo chown user:user /var/www/nison-analytics

scp -r dist/* user@your-vps-ip:/var/www/nison-analytics/
```

3. **Настройка Nginx:**
```bash
sudo nano /etc/nginx/sites-available/nison-analytics
```

```nginx
server {
    listen 80;
    server_name your-domain.com;
    
    root /var/www/nison-analytics;
    index index.html;
    
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
    
    gzip on;
    gzip_types text/plain text/css application/json application/javascript;
}
```

4. **Активация и SSL:**
```bash
sudo ln -s /etc/nginx/sites-available/nison-analytics /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### Вариант 2: Docker (рекомендуется)

**Dockerfile:**
```dockerfile
FROM node:18-alpine as builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**Деплой:**
```bash
docker build -t nison-analytics .
docker run -d -p 80:80 --name nison-analytics nison-analytics
```
