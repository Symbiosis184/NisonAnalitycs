### C1 — Гейт семьи шеи: книжное условие по цене ОТКРЫТИЯ — коммит `b20ce96`
Файл: `src/utils/pattern_engine.ts`, `isNeckFamily`.

**Цитата (ЯС, гл. 6, «Контратака»):**
> «Когда возникает модель „на шее", торги начинаются на отметке лишь немного ниже предыдущего уровня закрытия, а при формировании бычьей контратаки рынок открывается резким падением.»

**Было:** `if (!c2.isBullish || c2.open >= c1.low) return { found: false, name: '' };`
Так как `low₁ ≤ close₁` по определению свечи, а на круглосуточном рынке `open₂ ≈ close₁`,
условие `open₂ < low₁` невыполнимо — все три модели семьи шеи были недостижимы.

**Стало:**
```ts
const openTol = this.adaptiveTol([...prev.slice(-20), c1], 0.15);
if (!c2.isBullish || c2.open > c1.close + openTol) return { found: false, name: '' };
```
Открытие белой свечи ограничивается сверху уровнем **закрытия** чёрной с допуском
(«немного ниже / чуть выше»). Комментарий помечает: допуск `adaptiveTol(0.15)` и
распространение гейта на «ниже шеи» и «толчок» — проектная эвристика для рынков без
сессий (книга задаёт открытие только для «на шее» и без числового порога).
Привязки цен ЗАКРЫТИЯ оставлены как есть (см. C1b).

**Тесты:** `src/__tests__/unit/nison_neck_family_b1.test.ts` (контекст спада, c1 — длинная чёрная):
- open₂ = close₁, close₂ ≈ low₁ → «НИЖЕ ШЕИ» ✅
- open₂ = close₁, close₂ чуть выше close₁ → «НА ШЕЕ» ✅
- close₂ между close₁ и bodyMid₁ → «ТОЛЧОК» ✅
- open₂ выше close₁ более чем на допуск → `found === false` ✅
- контекст роста/боковика → `found === false` ✅

**Критерий выполнен:** при `open₂ == close₁` модель детектируется (раньше — никогда).

### C2 — RENKO: кирпич строится от границы предыдущего — коммит `d281111`
Файл: `src/utils/beyond_candlesticks.ts`, функция `renko`.

**Цитаты (ЗГ, гл. 7, правила 4 и 5):**
> «Правило 4. Если сегодняшняя цена закрытия выше вершины последнего кирпича (не важно, белый он или черный) на величину порога или более... Новый кирпич начинается с максимума предыдущего кирпича.»
> «Правило 5. Если сегодняшняя цена закрытия ниже основания последнего кирпича (белого или черного) на величину порога или более... если основание последнего кирпича находится на отметке 95, то... рынок должен опуститься хотя бы до 90. Такой кирпич будет располагаться в интервале от основания предыдущего кирпича до отметки 90.»

Разбор примера из книги (табл. 7.1): после чёрного кирпича 135→130 белый требует подъёма
до 140 (порог выше МАКСИМУМА 135), чёрный — падения до 125 (порог ниже МИНИМУМА 130).
Следствие: при развороте первый новый кирпич начинается от **противоположной границы**
последнего кирпича, а не от его дальнего края (`anchorPrice`).

**Изменение (триггер `|delta| ≥ 2·brick` не менялся):**
```ts
let start = anchorPrice;
if (reversal) start = direction === 'up' ? anchorPrice - brickSize : anchorPrice + brickSize;
const count = Math.floor(Math.abs(point.close - start) / brickSize);
if (count < 1) continue;
const step = nextDirection === 'up' ? brickSize : -brickSize;
for (let j = 0; j < count; j++) { const open = start + step * j; /* ... поля без изменений */ }
anchorPrice = start + step * count;
```

**Тесты** (`src/__tests__/unit/beyond_candlesticks.test.ts`, кирпич 5):
- белый [100→105], close 95 → ровно ОДИН чёрный [95→100], `reversal=true` ✅
- белый [100→105], close 90 → ДВА чёрных: [95→100], [90→95] ✅
- пример книги: чёрный [135→130], close 140 → ровно ОДИН белый [135→140] ✅
- чёрный [135→130], close 145 → ДВА белых [135→140], [140→145] ✅
- продолжение тренда: поведение не меняется ([100,105,110,115] → три белых без перекрытия) ✅
- существующий тест `[100,102,100.5,99,98]` закреплял перекрытие (отклонение от правил 4–5) —
  обновлён: разворотные кирпичи теперь [101→100], [100→99] (геометрия по книге; количество
  кирпичей то же). Обоснование обновления — цитаты правил 4–5 выше.
